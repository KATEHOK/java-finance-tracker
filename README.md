# java-finance-tracker

Итоговый проект по курсу "Принципы объектно-ориентированного программирования": консольное приложение для учета личных финансов. Доходы и расходы по категориям, бюджеты, статистика, оповещения и переводы между пользователями.

## Возможности

- Регистрация и вход по логину и паролю, пользователей сколько угодно. Пароль хранится только как хеш PBKDF2 с солью
- У каждого пользователя свой кошелек: категории, бюджеты, все доходы и расходы, баланс
- Категории создает сам пользователь, их можно переименовать и удалить (если в категории нет операций)
- Бюджет на категорию расходов: сколько потрачено и сколько осталось
- Статистика: общие доходы и расходы, суммы по категориям, состояние бюджетов, выборка по нескольким категориям и по периоду, вывод в консоль или в файл
- Оповещения: бюджет израсходован на 80%, бюджет превышен, расходы больше доходов, нулевой баланс
- Кошелек сохраняется в файл при выходе и загружается при входе
- Экспорт и импорт кошелька в CSV
- Переводы другому пользователю по логину: расход у отправителя, доход у получателя

## Установка и запуск

Нужна только JDK 25. Maven ставить не надо: в репозитории есть Maven Wrapper (`mvnw`), он сам скачает нужную версию. Внешних библиотек в рантайме нет, JUnit подтягивается Maven только для тестов.

```bash
git clone https://github.com/KATEHOK/java-finance-tracker.git
cd java-finance-tracker
./mvnw package
java -jar target/finance-tracker.jar
```

На Windows вместо `./mvnw` - `mvnw.cmd`.

Данные лежат в `data/` относительно текущей директории. Другую директорию можно передать первым аргументом:

```bash
java -jar target/finance-tracker.jar my-data
```

`java -jar target/finance-tracker.jar --help` (или `-h`) печатает строку запуска. Больше одного аргумента - ошибка.

Пароль при вводе в терминале не отображается. Если ввод идет не из терминала (например, из IDE или из файла), пароль читается обычной строкой.

## Команды

До входа доступны только `register`, `login`, `help` и `exit`.

| Команда | Что делает | Пример |
|---|---|---|
| `register <login>` | создать пользователя и сразу войти (пароль спросит дважды) | `register alice` |
| `login <login>` | войти, показать баланс и текущие оповещения | `login alice` |
| `logout` | сохранить кошелек и выйти из аккаунта | |
| `income <amount> <category> [date] [note]` | добавить доход | `income 60000 Зарплата` |
| `expense <amount> <category> [date] [note]` | добавить расход | `expense 300 Еда 2026-11-25 обед` |
| `category add <name>` | создать категорию | `category add "Коммунальные услуги"` |
| `category rename <old> <new>` | переименовать категорию (операции и бюджет переезжают вместе с ней) | `category rename Еда Продукты` |
| `category delete <name>` | удалить категорию без операций | `category delete Такси` |
| `category list`, `categories` | категории с суммами доходов, расходов и бюджетом | |
| `budget set <category> <amount>` | установить или изменить бюджет | `budget set Еда 4000` |
| `budget delete <category>` | убрать бюджет | `budget delete Еда` |
| `budget list`, `budgets` | бюджеты: лимит, потрачено, осталось | |
| `balance` | общие доходы, расходы и баланс | |
| `report [category...] [--from <date>] [--to <date>] [--file <path>]` | статистика, при желании по выбранным категориям, за период и в файл | `report Еда Такси --from 2026-11-01 --to 2026-11-30` |
| `history [n]` | последние операции таблицей (по умолчанию все) | `history 10` |
| `alerts` | текущие оповещения | |
| `transfer <login> <amount> [note]` | перевести деньги другому пользователю | `transfer bob 500 за пиццу` |
| `export <file>` | сохранить кошелек в CSV | `export wallet.csv` |
| `import <file>` | добавить в кошелек данные из CSV | `import wallet.csv` |
| `help`, `h` | список команд с примерами | |
| `exit`, `quit` | сохранить кошелек и выйти | |

Правила ввода:

- Сумма - положительное число, копейки через точку или запятую: `1500`, `99.90`, `99,9`
- Дата - `ГГГГ-ММ-ДД`, если ее не указать, берется сегодняшняя. Можно указать и будущую дату, например для запланированного платежа. Заметка - до 150 символов, в переводе чуть меньше: к ней добавляется, от кого или кому перевод. Все, что после даты (или после категории, если даты нет), считается заметкой
- Названия с пробелами берутся в кавычки: `expense 3000 "Коммунальные услуги"`. Регистр в названиях категорий не важен: `еда` и `Еда` - одна категория, показывается так, как ее создали
- Логин - от 3 до 20 латинских букв, цифр или `_`, без учета регистра. Пароль - от 6 до 64 символов
- Неизвестная команда, неверная сумма или дата, неизвестная категория, лишние или недостающие аргументы - программа пишет, что не так, и подсказывает правильный вариант

## Оповещения

| Оповещение | Когда |
|---|---|
| `Food budget is 85% used (3,400.00 of 4,000.00)` | потрачено 80% бюджета категории или больше, но не сверх него |
| `Food budget is exceeded by 500.00 (4,500.00 of 4,000.00)` | расходы по категории больше бюджета |
| `Expenses exceed income by 500.00` | общие расходы больше общих доходов (баланс отрицательный) |
| `Your balance is zero` | баланс ровно ноль |

Оповещение выводится сразу после операции (расход, доход, перевод, изменение бюджета), если она перешла порог. Одно и то же оповещение не повторяется на каждую команду. Исключение - перерасход: если записать расход в категорию, где бюджет уже превышен, оповещение будет снова. При входе и после `import` выводятся все текущие оповещения, в любой момент их показывает команда `alerts`.

Бюджеты считаются за все время, а не за месяц: в ТЗ периодов у бюджета нет. Поэтому и в `report --from ... --to ...` раздел бюджетов показывает траты за все время, и это подписано в заголовке: `Budgets (spent for all time):`.

## Хранение данных

Пока программа работает, все данные живут в памяти. На диске:

- `data/users.tsv` - логины и хеши паролей: `login<TAB>соль<TAB>хеш`, соль и хеш в base64
- `data/wallets/<login>.csv` - кошелек пользователя

Кошелек пишется в файл при `logout`, `exit`, конце ввода (Ctrl+D) и при остановке программы по Ctrl+C, а читается при `login`. Если записать не удалось, `logout` и `exit` оставляют пользователя в программе: можно повторить или сохранить копию через `export`. Перевод сразу сохраняет кошельки обоих пользователей, потому что получатель в этот момент не в программе. Файлы пишутся атомарно: сначала во временный файл рядом, потом `move`, так что при падении программы старый файл останется целым. Если Ctrl+C пришел посреди команды, программа сначала ее доделывает, а потом сохраняет кошелек, чтобы, например, перевод не записался наполовину. Одну директорию данных должна использовать одна запущенная программа: список пользователей читается при старте и переписывается целиком.

`export`, `import` и `report --file` не работают с файлами внутри директории данных, чтобы случайно не затереть `users.tsv` или чужой кошелек и не прочитать чужой кошелек без пароля.

Формат CSV один и тот же для файла кошелька и для `export`/`import`:

```
type,date,category,amount,note
category,,Еда,,
budget,,Еда,4000.00,
expense,2026-11-25,Еда,300.00,обед
income,2026-11-25,Зарплата,20000.00,
```

Поля с запятыми и кавычками берутся в кавычки по RFC 4180. Строки `category` и `budget` необязательны: если в файле есть только операции, категории создаются сами, поэтому можно импортировать и таблицу, собранную вручную. При ошибке в файле программа пишет номер строки и что с ней не так, и ничего не импортирует.

`import` добавляет недостающие категории, бюджеты для категорий, где своего бюджета нет, и все операции из файла. Повторный импорт того же файла добавит операции еще раз: одинаковые операции (например, два обеда по 300 в один день) бывают и на самом деле, поэтому дубли не отбрасываются.

## Архитектура

Три слоя, зависимости идут только внутрь: cli и infra знают про core, core ни про кого.

```
io.github.katehok.finance
├── Main                 сборка всех зависимостей руками (DI без фреймворка)
├── core                 модель и бизнес-логика, без ввода/вывода
│   ├── Money                    сумма в копейках (record), разбор и формат
│   ├── Operation                sealed-интерфейс операции
│   │   ├── Income               доход (record)
│   │   └── Expense              расход (record)
│   ├── Category                 категория и ее бюджет
│   ├── Wallet                   кошелек: категории, бюджеты, операции, баланс
│   ├── User                     пользователь: логин и его кошелек
│   ├── Password                 хеш пароля PBKDF2 с солью
│   ├── Alert                    оповещение (record с enum Type)
│   ├── AuthService              регистрация, вход, сохранение кошелька
│   ├── WalletService            операции, категории, бюджеты, переводы, экспорт/импорт
│   ├── ReportService            статистика и выборки (Filter, Report - вложенные record)
│   ├── AlertService             проверка порогов, какие оповещения новые
│   ├── FinanceException         ошибка с причиной (enum Reason)
│   └── UserRepository, WalletRepository, WalletFormat   интерфейсы хранилищ
├── infra                реализации интерфейсов
│   ├── MemoryUserRepository, FileUserRepository       пользователи в памяти / в файле
│   ├── MemoryWalletRepository, FileWalletRepository   кошельки в памяти / в файлах
│   ├── CsvWalletFormat          чтение и запись кошелька в CSV
│   └── AtomicFile               атомарная запись файла
└── cli                  консольный интерфейс
    ├── Cli                      цикл: строка -> команда из реестра -> выполнение, ошибки с подсказками
    ├── Tokenizer                разбиение строки на слова с учетом кавычек
    ├── Table                    выравнивание колонок
    ├── ReportFormatter          текст отчета для консоли и файла
    ├── Messages                 тексты оповещений и ошибок ввода-вывода
    └── command                  команды
        ├── Command                  интерфейс команды: имя, синонимы, usage, строки help, execute
        ├── CommandRegistry          реестр команд по имени и синонимам
        ├── Session                  текущий пользователь, ввод и вывод, сохранение кошелька
        ├── Args                     разбор чисел, сумм и дат из аргументов
        ├── Shortcut                 короткая форма команды (categories = category list)
        ├── OperationCommand         общий разбор income/expense
        │   ├── IncomeCommand
        │   └── ExpenseCommand
        └── RegisterCommand, LoginCommand, LogoutCommand, CategoryCommand, BudgetCommand,
            BalanceCommand, ReportCommand, HistoryCommand, AlertsCommand, TransferCommand,
            ExportCommand, ImportCommand, HelpCommand, ExitCommand
```

### Модули

- **core** - вся логика. Ничего не читает с консоли и не пишет в файлы, поэтому тестируется без ввода/вывода. Сервисы получают хранилища и часы через конструктор и зависят только от интерфейсов.
- **infra** - работа с файлами. `FileWalletRepository` сам CSV не разбирает, а отдает это `CsvWalletFormat`, тому же, что используется для `export`/`import`, так что формат описан в одном месте. Memory-хранилища нужны для тестов.
- **cli** - только ввод и вывод: разбирает команду, вызывает сервис, печатает результат или ошибку с подсказкой. Правил предметной области здесь нет: например, проверка, что категория существует, живет в `Wallet`. Каждая команда - отдельный класс, реализующий `Command`. `Cli` находит ее в `CommandRegistry` по первому слову, проверяет, нужен ли вход, и вызывает `execute`. Новая команда - это новый класс и одна строка регистрации, `Cli` при этом не меняется. Справка собирается из самих команд.

### ООП в проекте

- **Инкапсуляция.** `Wallet` никому не отдает свои коллекции: `getOperations()` и `getCategories()` возвращают неизменяемые копии, а менять кошелек можно только его методами, которые проверяют инварианты (категория существует, имена не повторяются, бюджет положительный). Сеттеры `Category` package-private, поэтому снаружи core бюджет мимо кошелька не поменять. Баланс не хранится, а считается из операций, так что рассинхронизироваться ему не с чем.
- **Композиция.** `User` владеет `Wallet`, кошелек владеет категориями и операциями. Сервисы собраны из хранилищ, `AlertService` и часов, которые им передают снаружи.
- **Полиморфизм и sealed-иерархия.** `Operation` - `sealed interface` с двумя record: `Income` и `Expense`. Каждая операция сама знает, как менять баланс (`applyTo`), поэтому `Wallet.getBalance()` просто проходит по списку, не выясняя тип. Хранилища - интерфейсы с файловой реализацией и реализацией в памяти, сервисы не знают, какая из них им досталась. Консольные команды реализуют общий интерфейс `Command`, и `Cli` вызывает их одинаково, не зная конкретного класса. `IncomeCommand` и `ExpenseCommand` наследуют `OperationCommand`: разбор аргументов и вывод общие, отличается только метод `add` (шаблонный метод).
- **Неизменяемые значения.** `Money`, операции, `Alert` и результаты отчета - record: их можно спокойно отдавать наружу, `equals`/`hashCode` сгенерированы.

### Решения

- **Деньги.** Суммы хранятся в копейках в `long`, а не в `double`: у `double` 0.1 + 0.2 не равно 0.3. Переполнение проверяется (`Math.addExact`), сумма одной операции - не больше 10^12 рублей.
- **Пароли.** PBKDF2WithHmacSHA256 из JDK, 100 000 итераций, своя случайная соль у каждого пользователя. Хеши сравниваются `MessageDigest.isEqual` за постоянное время. На неверный пароль и неизвестный логин ответ одинаковый.
- **Переводы.** Отправитель не может перевести больше, чем у него на балансе, и не может перевести сам себе. У обоих операция попадает в категорию `Transfers` (создается сама), в заметке указано, от кого или кому.
- **Удаление категории.** Категорию, в которой есть операции, удалить нельзя, иначе пропала бы история. Ее можно переименовать.

## Тестирование

```bash
./mvnw test
```

272 теста на JUnit 5:

- **unit**:
  - `core`: деньги, операции, кошелек, пароли, все сервисы и пороги оповещений
  - `infra`: CSV (разбор, кавычки, ошибки с номером строки), файловые хранилища, восстановление после неудачной записи
  - `cli`: каждая команда и сообщения об ошибках, разбор кавычек, таблицы, реестр команд, команды операций отдельно от консоли
  - `Main`: `--help`, лишние аргументы, битый файл пользователей
- **интеграционные** (`ScenarioTest`): программа целиком через консольный интерфейс на настоящих файлах во временной директории, каждый запуск - новые объекты на тех же файлах, как после перезапуска:
  - пример из ТЗ: отчет совпадает построчно, оповещения выводятся в нужный момент
  - после перезапуска кошелек и пароль на месте, при входе показываются оповещения
  - кошелек сохраняется по `logout`, `exit` и по концу ввода
  - `export`, `import` и `report --file` отказываются трогать файлы в директории данных
  - перевод другому пользователю виден у обоих после перезапуска
  - экспорт у одного пользователя и импорт у другого дают тот же отчет
  - у разных пользователей разные кошельки

## Качество кода и CI

- `.editorconfig` - отступы, кодировка, переводы строк
- Spotless - проверка форматирования: `./mvnw spotless:check` (или `./mvnw -Plint verify`, тогда проверка идет вместе со сборкой)
- Компилятор с `-Xlint:all,-serial` и `failOnWarning`: любое предупреждение ломает сборку
- GitHub Actions (`.github/workflows/ci.yml`): на каждый push в любую ветку и на каждый pull request в main - линт, сборка и тесты на JDK 25
